# ADR 0007: Явное согласие и модерация для текстовых вкладов

## Контекст

Пользователи создают личные ассоциации, которые могут улучшить общий контент. Нужно делиться ими добровольно, не передавая изображения и не публикуя ничего автоматически.

## Решение

- Вклад — только текст: `cueWord`, `sceneText`, ids слова/ассоциации, версия согласия и время.
- Согласие имеет статусы `unset`, `granted`, `declined`, `ask_later`, `withdrawn`.
- Диалог показывается авторизованному пользователю после третьей созданной ассоциации, если статус `unset` и диалог не показывался в этой сессии.
- `ask_later` откладывает повтор на 30 дней и ещё три создания; `declined` не повторяется автоматически; `withdrawn` останавливает отправку и очищает очередь.
- Сервер проверяет `granted` при каждом batch и возвращает `403 CONSENT_REQUIRED`.
- Batch: до 50 записей, идемпотентность по `(contributor_user_id, client_contribution_id)` и нормализованному хешу, rate limit 30 запросов в час на пользователя в пределах процесса.
- Клиенты держат локальную очередь (mobile SQLite, web localStorage) и повторяют отправку с backoff; `403` останавливает очередь.
- Подозрительный текст (email, телефон, URL) сохраняется как `pending` с флагами и уходит на ручную модерацию.
- `approve` означает «одобрено для ручной редактуры», а не публикацию. Публикация — отдельный процесс.
- `withdrawn` — терминальный статус; дальнейшие решения возвращают `409`.
- Модератор видит псевдонимный HMAC-идентификатор автора, но не email и не сырой `userId`.
- Решения и активации фиксируются в `audit_log`.

## Почему

- Согласие явное, без предустановленных галочек.
- Серверная проверка не позволяет обойти клиентскую логику.
- Текст без изображений снижает риск утечки личных файлов.
- Ручная модерация защищает от PII, спама и автоматической публикации.
- Идемпотентность и очередь переживают перезапуск и потерю сети.

## Последствия

- Одобренный вклад не появляется в контенте сам: нужен редакционный процесс.
- `withdrawn` и `rejected` строки хранятся для истории; жёсткого удаления через API нет.
- Rate limit не распределён между инстансами; для строгого лимита нужен Redis или счётчик в БД.
- Нет UI экспорта и удаления аккаунта.
- Сервер хранит `nextPromptAt`, но не локальный `promptAfterCount`; при отсутствии локального счётчика повтор показывается по дате.
