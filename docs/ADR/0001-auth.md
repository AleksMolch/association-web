# ADR 0001: Better Auth вместо собственной auth

## Контекст

Нужны регистрация, вход, сессии, подтверждение email, сброс пароля и защита от типовых атак.

## Решение

Использовать Better Auth с Drizzle adapter и PostgreSQL.

## Почему

- Проверенные password hashing и session handling.
- Встроенные verification/reset/rate limit.
- Next.js cookies через `nextCookies()`.
- Меньше собственного security-кода.

## Последствия

- Схема `user/session/account/verification` должна совпадать с ожиданиями Better Auth.
- Обновления библиотеки требуют проверки миграций.
- OAuth и MFA не включены.
