# Приватность и обработка данных

Это инженерное описание фактического поведения продукта, не юридическая консультация. Перед публикацией в РФ политику нужно проверить по 152-ФЗ (см. [SECURITY.md](SECURITY.md)).

## Принципы

- Минимум данных: для обучения аккаунт не обязателен.
- Текст личных ассоциаций при входе синхронизируется с аккаунтом; изображения не загружаются на сервер и не синхронизируются.
- Вклады в банк идей отправляются только после явного согласия и только текстом.
- Согласие можно отозвать; это останавливает новые отправки и очищает неотправленную очередь, а уже переданные вклады отзываются отдельным действием.
- Модерация не публикует контент автоматически.

## Какие данные обрабатываются

| Категория | Состав | Где хранится |
| --- | --- | --- |
| Аккаунт | email, имя, хеш пароля, сессии | PostgreSQL |
| Прогресс | карточки FSRS, отзывы, выборы, настройки | локально и/или PostgreSQL |
| Личные ассоциации | `cueWord`, `sceneText`, `wordId`, `meaningId`, `rev`, `deletedAt` | локально; в облаке — при входе/синхронизации |
| Локальные изображения | файл, MIME, размеры, checksum, локальный URI | только устройство (mobile document directory / web IndexedDB) |
| Согласие на вклады | статус, версия согласия, `decidedAt`, `nextPromptAt` | локально + PostgreSQL |
| Вклады | текст ассоциации, ids слова/ассоциации, версия согласия, время | PostgreSQL |
| Модерация | статус, причина, псевдонимный автор, `reviewedBy`, `reviewedAt` | PostgreSQL + `audit_log` |
| Платежи | тариф, сумма, статус, id провайдера | PostgreSQL; карточные данные остаются в ЮKassa |
| Технические логи | метки endpoint и статус ошибки | инфраструктура хостинга |

Не собираем адрес, телефон, паспортные данные и платёжные реквизиты карты. Телефон/email могут встретиться в свободном тексте ассоциации — такой вклад помечается флагом и уходит на ручную модерацию.

## Локальные изображения

- Mobile: `documentDirectory/user-mnemonics/<mnemonicId>.jpg`.
- Web: IndexedDB `association-user-images` / object store `images`.
- В сетевых запросах, sync/contribution payload и логах нет файла, URI, имени файла, base64, MIME, размеров и EXIF.
- На другом устройстве изображения нет: показывается placeholder и предложение добавить своё.
- Очистка данных приложения или браузера удаляет изображения без возможности восстановления.

Подробнее — [ADR 0006](ADR/0006-user-mnemonics-local-images.md).

## Согласие на вклады

Статусы: `unset`, `granted`, `declined`, `ask_later`, `withdrawn`.

- Диалог появляется после третьей созданной ассоциации, только авторизованному пользователю, один раз за сессию.
- `granted` — новые и изменённые ассоциации могут попадать в очередь отправки.
- `declined` — автоматический повторный показ не выполняется.
- `ask_later` — повтор не раньше чем через 30 дней и после ещё трёх созданий.
- `withdrawn` — новые отправки прекращаются и очищается неотправленная локальная очередь. Ранее переданные вклады отзываются отдельным действием через API, а не автоматически при смене согласия или удалении ассоциации.
- Настройка меняется в любой момент; сервер проверяет `granted` при каждом batch.

Подробнее — [ADR 0007](ADR/0007-contributions-consent.md).

## Модерация и публикация

- Модератор видит текст вклада и псевдонимный `contributorId` (HMAC от `userId` с `MODERATION_PSEUDONYM_SECRET`).
- Email и сырой `userId` в очередь не возвращаются.
- `approve` значит «одобрено для ручной редактуры». Автоматической публикации нет.
- `withdrawn` — терминальный статус, дальнейшие решения отклоняются.
- Решения фиксируются в `mnemonic_contributions` и `audit_log`.

## Сроки хранения

Рекомендуемая политика:

| Данные | Срок |
| --- | --- |
| Активные личные ассоциации | до удаления пользователем |
| Tombstone личной ассоциации | до синхронизации удаления и последующей очистки; физическая очистка пока не реализована, текст остаётся в строке |
| Вклады `pending`/`approved`/`duplicate` | до отзыва или завершения редакционного цикла |
| Вклады `withdrawn`/`rejected` | хранятся для истории модерации и защиты от повторной отправки; жёсткого удаления через API нет |
| `audit_log` | не менее 1 года |
| Платежи и подписки | срок, требуемый бухгалтерией и законом |
| Сессии и verification | до истечения и автоматической очистки |

После SQL-удаления `user` каскадно удаляются прогресс, личные ассоциации, настройки согласия, платежи и подписки. Вклады сохраняются обезличенными (`contributor_user_id = null`), `audit_log.actor_id` становится `null`.

## Права пользователя

- Отозвать уже переданные вклады можно отдельным действием в настройках приватности.
- Удалить личную ассоциацию можно в карточке слова; это не отзывает ранее отправленные вклады.
- Экспорт данных и удаление аккаунта через UI пока не реализованы — это follow-up. До появления UI удаление выполняется SQL-запросом администратором.

## Третьи стороны

- ЮKassa — приём платежей; карточные данные не проходят через приложение.
- Resend — транзакционные письма (сброс пароля, подтверждение email).
- Хостинг и PostgreSQL — хранение серверных данных.
- Аналитики и рекламных SDK в текущей реализации нет.

## Логи

- Не логируются пароли, токены, cookie, секреты, `sceneText`, `cueWord`, media URI и содержимое sync/contribution payload.
- Ошибки новых API логируются статической меткой без объекта ошибки, чтобы параметры запроса не попали в лог.
- В development письмо логируется с маскированным получателем, без ссылки и токена.
- Срок хранения логов и доступ настраиваются на уровне инфраструктуры.

## Известные ограничения

- Нет UI экспорта/удаления аккаунта.
- Нет физической очистки tombstone и withdrawn-вкладов.
- Rate limit вкладов действует в пределах одного процесса.
- CSP пока не настроен; действуют базовые security headers (см. [SECURITY.md](SECURITY.md)).
- Юридические тексты и согласия требуют проверки юристом.
