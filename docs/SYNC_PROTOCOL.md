# Протокол синхронизации

## Границы

| Клиент | Endpoint | Доступ | Что синхронизируется |
| --- | --- | --- | --- |
| Web | `GET/POST /api/progress` | любой авторизованный аккаунт | карточки, выборы, настройки, отзывы (POST), тексты личных ассоциаций |
| Mobile | `GET/POST /api/mobile/sync` | активный VIP | карточки, отзывы, выборы, настройки, тексты личных ассоциаций |

Изображения личных ассоциаций не синхронизируются ни на одном endpoint. Локальные URI и media-поля отклоняются строгими схемами.

## DTO веб-прогресса

`POST /api/progress`:

```json
{
  "cards": [CardRow],
  "selections": { "wordId": "mnemonicId" },
  "settings": Settings,
  "reviews": [ReviewRow],
  "userMnemonics": [UserMnemonic]
}
```

`GET /api/progress` возвращает `cards`, `selections`, `settings`, `userMnemonics`. Отзывы в ответ не входят.

`CardRow` содержит `rev` — монотонную ревизию FSRS-состояния.

`UserMnemonic`:

```json
{
  "id": "usr-...",
  "wordId": 42,
  "meaningId": "0",
  "cueWord": "Брат",
  "sceneText": "Брат светит фонарём",
  "locale": "ru",
  "createdAt": "2026-11-04T00:00:00.000Z",
  "updatedAt": "2026-11-04T00:00:00.000Z",
  "deletedAt": null,
  "rev": 1
}
```

`deletedAt` — tombstone. В payload нет полей `image`, `uri`, `fileName`, `base64`, `media`, `mimeType`, `width`, `height`, `byteSize`, `checksum`.

## DTO мобильной синхронизации

`GET /api/mobile/sync`:

```json
{
  "cards": [CardRow],
  "reviews": [ReviewRow],
  "selections": [{ "wordId": 42, "mnemonicId": "0", "updatedAt": "..." }],
  "settings": {
    "dailyGoal": 10,
    "hintsEnabled": true,
    "reducedMotion": false,
    "ttsRate": 0.95,
    "updatedAt": "..."
  },
  "userMnemonics": [UserMnemonic]
}
```

`POST /api/mobile/sync` принимает тот же снимок. Ответ — актуальное состояние после merge.

Коды:

- `401 UNAUTHORIZED` — нет сессии;
- `403 VIP_REQUIRED` — сессия есть, активной VIP-подписки нет;
- `400 INVALID_BODY` — нарушена схема, включая media-поля;
- `503 SYNC_FAILED` — ошибка БД/сервера.

## Конфликты

- Карточки: last-write-wins по `rev`; при равенстве — по `updatedAt`.
- Личные ассоциации: last-write-wins по `rev`; при равенстве — по `updatedAt`; при полном равенстве tombstone побеждает активную запись.
- Выборы: last-write-wins по `updatedAt`.
- Настройки: last-write-wins по `updatedAt`.
- Отзывы: только вставка, дубликаты по id игнорируются.
- Сервер не пересчитывает FSRS: он хранит результат клиента.

Tombstone не воскресает: входящая запись с меньшим `rev` не перезаписывает удалённую, а удаление с большим `rev` скрывает активную на другом устройстве.

## Offline

- Гость и авторизованный пользователь работают локально.
- При отсутствии сети запись в localStorage/SQLite продолжается.
- Веб: после входа доступна кнопка «Перенести прогресс в облако».
- Mobile: синхронизация запускается вручную; автоматической фоновой синхронизации нет.
- Конфликт между двумя устройствами решает `rev`/`updatedAt`; более старый снимок не затирает новый.
- Мобильный клиент отправляет отзывы чанками до 10 000; остальные сущности — одним снимком.
- При истечении VIP мобильный клиент выходит из аккаунта, сохраняя локальные данные и базовое обучение.

## Идентификаторы

- Клиент: `wordId:meaningId:en-ru` для карточки; `usr-...` для личной ассоциации до синхронизации.
- Сервер: `${userId}:${clientId}` для карточек, отзывов и личных ассоциаций.
- Отзывы: `${userId}:${clientReviewId}`.
- Это исключает коллизии между пользователями.

## Очередь вкладов

Это не часть sync-снимка, а отдельная очередь:

- Mobile: SQLite `contribution_outbox`; web: `localStorage` `association_contribution_outbox_v1:<userId>`.
- Отправка только при локальном согласии `granted` и активной сессии.
- Batch до 50; отзыв до 200 id.
- Повтор с backoff: база 60 секунд, максимум 1 час.
- `403` останавливает очередь; `401` требует повторного входа.
- В payload только текст и ids, без изображений и URI.

## Совместимость контента

- Контент версионируется в `words.json` (`version`).
- `wordId` стабилен; удаление слов ломает прогресс.
- Новые слова добавляются в конец.
- При несовместимом изменении поднять версию и добавить миграцию/фильтрацию.
- Сервер не проверяет, что `wordId` существует, для прогресса; для вкладов и CRUD ассоциаций проверяет.

## Ограничения

- Нет websocket/push.
- Нет разрешения конфликтов на уровне полей.
- Нет журнала изменений для UI.
- `DELETE /api/progress` не подключён к интерфейсу и не удаляет личные ассоциации.
- Изображения не восстанавливаются на другом устройстве.
- Нет автоматической фоновой синхронизации на mobile.
