# Протокол синхронизации

## DTO

`POST /api/progress`:

```json
{
  "cards": [CardRow],
  "selections": { "wordId": "mnemonicId" },
  "settings": Settings,
  "reviews": [ReviewRow]
}
```

`CardRow` содержит `rev` — монотонную ревизию FSRS-состояния.

## Конфликты

- Карточки: last-write-wins по `rev` (`incoming.rev > stored.rev`).
- Выборы: последний запрос перезаписывает.
- Настройки: последний запрос перезаписывает.
- Отзывы: только вставка, дубликаты игнорируются.
- Сервер не пересчитывает FSRS: он хранит результат клиента.

## Offline

- Гость и авторизованный пользователь работают локально.
- При отсутствии сети запись в localStorage продолжается.
- После входа доступна кнопка «Перенести прогресс в облако».
- Автоматическая фоновая синхронизация не реализована.
- Конфликт между двумя устройствами решает `rev`; более старый снимок не затирает новый.

## Идентификаторы

- Клиент: `wordId:meaningId:en-ru`.
- Сервер: `${userId}:${clientCardId}`.
- Отзывы: `${userId}:${clientReviewId}`.
- Это исключает коллизии между пользователями.

## Совместимость контента

- Контент версионируется в `words.json` (`version`).
- `wordId` стабилен; удаление слов ломает прогресс.
- Новые слова добавляются в конец.
- При несовместимом изменении поднять версию и добавить миграцию/фильтрацию.
- Сервер не проверяет, что `wordId` существует; это делает контент-тест.

## Ограничения

- Нет websocket/push.
- Нет разрешения конфликтов на уровне полей.
- Нет журнала изменений для UI.
- `DELETE /api/progress` не подключён к интерфейсу.
