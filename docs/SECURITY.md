# Безопасность

Это инженерный чек-лист, не юридическая консультация.

## Аутентификация

- Better Auth, email + пароль, минимум 8 символов.
- Пароли хешируются адаптером Better Auth; в приложении нет собственного хранения паролей.
- Сессия — HttpOnly cookie, 30 дней, обновление раз в сутки.
- В production требуется подтверждение email.
- Сброс пароля одноразовый, срок действия — 1 час.
- Роль `admin` — additional field с `input: false`; клиент не может назначить её себе.
- Origin проверяется Better Auth; `trustedOrigins` ограничен публичным URL.

## Авторизация

- `/api/progress` требует сессию.
- `/api/billing/create-payment` и `/api/billing/status` требуют сессию.
- `/admin` проверяет `session.user.role === "admin"` на сервере.
- Каждый запрос прогресса и платежей фильтруется по `userId` из сессии, а не из тела.

## Платежи

- Сумма и срок берутся только из серверного `plans.ts`.
- VIP активирует только webhook ЮKassa.
- Return URL не считается подтверждением оплаты.
- Webhook идемпотентен: повторный `payment.succeeded` не создаёт вторую подписку.
- `Idempotence-Key` уникален для каждого платежа.
- Рекомендуется включить allowlist IP ЮKassa.
- Секретный ключ ЮKassa не передаётся в браузер.

## Данные

Собираем минимум:

- email, имя;
- progress: wordId, FSRS-параметры, выбранная ассоциация;
- отзывы: оценка, факт подсказки, время;
- платежи: сумма, статус, идентификаторы провайдера.

Не собираем без необходимости:

- адрес, телефон, паспортные данные;
- платёжные реквизиты карты (ими владеет ЮKassa);
- произвольные заметки пользователя.

## Логи

- Не логировать пароли, токены сброса, cookie и секреты.
- В development письмо логируется без ссылки и токена.
- Ошибки платежей логируются с усечённым ответом провайдера.
- Перед production настроить срок хранения логов и доступ.

## Известные ограничения

- Нет OAuth и 2FA.
- Нет автоматического удаления аккаунта через UI.
- Нет защиты от распределённого брутфорса beyond Better Auth rate limit.
- Нет CSP; базовые security headers заданы в `next.config.ts`.
- Нет аудита всех действий пользователя, только активация подписки.
