# Пользовательские ассоциации

Личная ассоциация — это пара «созвучие + сцена» (`cueWord`, `sceneText`), которую пользователь создаёт сам для слова из контент-пака. Она хранится отдельно от встроенных ассоциаций и может иметь локальное изображение. Изображение никогда не покидает устройство.

## Возможности

- создание, редактирование и удаление личной ассоциации;
- выбор личной ассоциации для слова без сброса FSRS-прогресса;
- тренировка с выбранной личной ассоциацией;
- необязательное локальное изображение;
- синхронизация текста между устройствами (VIP для мобильного клиента, бесплатно для веб-аккаунта);
- добровольная передача текста в банк идей после явного согласия.

## Ограничения полей

| Поле | Правило |
| --- | --- |
| `cueWord` | 1–80 символов после trim |
| `sceneText` | 5–500 символов после trim |
| `meaningId` | 1–32 символа |
| `locale` | строго `"ru"` |
| `wordId` | должен существовать в текущем контент-паке |

Zod-схемы строгие (`.strict()`): поля `image`, `uri`, `fileName`, `base64`, `media`, `userId` и любые другие лишние ключи отклоняются с `400`. HTML не хранится и не рендерится как HTML: `<script>` остаётся текстом.

## Где хранятся данные

### Мобильное приложение

| Данные | Хранилище |
| --- | --- |
| Текст ассоциации, `rev`, `deletedAt` | SQLite, таблица `user_mnemonics` |
| Метаданные изображения | SQLite, таблица `local_mnemonic_media` |
| Очередь вкладов | SQLite, таблица `contribution_outbox` |
| Метаданные синхронизации | SQLite, таблица `sync_meta` |
| Файл изображения | `documentDirectory/user-mnemonics/<mnemonicId>.jpg` |

Изображение читается из picker, проверяется по размеру, MIME и magic bytes, перекодируется в JPEG и уменьшается до стороны 1600 px. Вход: до 12 МиБ и 24 МП; выход: JPEG до 2 МиБ. SVG, GIF, HTML-маскировка и несоответствие сигнатуры отклоняются.

### Веб-версия

| Данные | Хранилище |
| --- | --- |
| Текст ассоциации и метаданные | `localStorage`, ключ `association_guest_v1` (общий guest-store) |
| Файл изображения | IndexedDB `association-user-images`, object store `images` |
| Очередь вкладов | `localStorage`, ключ `association_contribution_outbox_v1:<userId>` |

Web принимает JPEG/PNG/WebP (HEIC/HEIF не поддерживаются), предпочитает WebP и откатывается на JPEG; результат ограничен 1600 px и 2 МиБ. Локальная ссылка на изображение имеет вид `indexeddb://...` и используется только браузером. В sync и contribution payload попадает только текст.

## Серверные endpoints

| Метод | Путь | Доступ | Назначение |
| --- | --- | --- | --- |
| `GET` | `/api/user-mnemonics?wordId=` | сессия | активные ассоциации владельца |
| `POST` | `/api/user-mnemonics` | сессия | создать текстовую ассоциацию |
| `PATCH` | `/api/user-mnemonics/:id` | сессия | изменить `cueWord`/`sceneText` |
| `DELETE` | `/api/user-mnemonics/:id` | сессия | поставить tombstone |
| `GET` | `/api/progress` | сессия | веб-прогресс + тексты ассоциаций |
| `POST` | `/api/progress` | сессия | принять веб-снимок прогресса |
| `GET` | `/api/mobile/sync` | сессия + активный VIP | полный снимок для мобильного клиента |
| `POST` | `/api/mobile/sync` | сессия + активный VIP | слить и сохранить полный снимок |

`POST /api/user-mnemonics` принимает `{ wordId, meaningId, cueWord, sceneText }`. `PATCH` принимает хотя бы одно из полей `cueWord`, `sceneText`. Серверный id имеет вид `${userId}:${uuid}`. Чужие и удалённые записи возвращают `404`.

`DELETE` не стирает строку физически: выставляет `deletedAt` и увеличивает `rev`. Tombstone нужен, чтобы удаление доехало до других устройств и не «воскресло» со старым `rev`. Повторное удаление идемпотентно.

## Синхронизация

- Веб-аккаунт: `/api/progress` доступен без VIP и синхронизирует текст ассоциаций, карточки, выборы и настройки.
- Мобильный клиент: `/api/mobile/sync` требует активной VIP-подписки; без неё — `403 VIP_REQUIRED`.
- Карточки и личные ассоциации сравниваются по `rev`, затем `updatedAt`; при равенстве tombstone побеждает активную запись.
- Выборы и настройки сравниваются по `updatedAt`.
- Отзывы вставляются идемпотентно; мобильный клиент отправляет их частями до 10 000 за запрос.
- Изображения не участвуют в синхронизации. На другом устройстве показывается честный placeholder «изображение сохранено на другом устройстве» с действием добавить локальное изображение.
- Мобильный клиент при истечении VIP выходит из аккаунта, но сохраняет локальные данные и базовое обучение.

Подробнее — [SYNC_PROTOCOL.md](SYNC_PROTOCOL.md).

## Вклады в банк идей

Передаётся только текст: `clientContributionId`, `sourceMnemonicId`, `wordId`, `meaningId`, `cueWord`, `sceneText`, `locale`, `consentVersion`, `submittedAt`. Ни файл, ни URI, ни имя файла, ни MIME, ни размеры, ни EXIF не передаются.

- Согласие: `unset | granted | declined | ask_later | withdrawn`.
- Диалог показывается авторизованному пользователю после третьей созданной ассоциации, если статус `unset` и диалог ещё не показывался в этой сессии.
- `ask_later` откладывает повторный показ на 30 дней и ещё три новых создания.
- `declined` не показывает автоматический повторный запрос; настройку можно изменить вручную.
- `withdrawn` останавливает новые отправки и очищает ещё не отправленную локальную очередь.
- Отзыв уже переданных вкладов — отдельное действие (кнопка «Удалить ранее переданные варианты» / `POST /withdraw`). Удаление личной ассоциации само по себе не отзывает отправленные вклады.
- Сервер проверяет согласие сам: без `granted` batch возвращает `403 CONSENT_REQUIRED`. Клиентская проверка — только UX.
- Batch: до 50 записей, идемпотентность по `(contributor_user_id, client_contribution_id)` и нормализованному хешу текста.
- Rate limit: 30 batch-запросов на пользователя в час в пределах одного процесса.
- Подозрительный текст (email, телефон, URL) сохраняется как `pending` с флагами для ручной модерации и не одобряется автоматически.
- Очередь повторяет отправку с backoff (60 секунд, максимум 1 час); `403` останавливает очередь.
- Отзыв: `POST /api/mnemonic-contributions/withdraw` переводит свои `pending`/`approved`/`duplicate` записи в `withdrawn`.

Модерация: очередь по умолчанию показывает `pending`, limit по умолчанию 50, максимум 200. `approve` означает «одобрено для ручной редактуры», а не публикацию. Публикация общего контента выполняется отдельным процессом и не происходит автоматически. `withdrawn` — терминальный статус; другие действия по нему возвращают `409`. Админ видит текст и псевдонимный `contributorId`, но не email и не сырой `userId`.

Подробнее — [ADR 0007](ADR/0007-contributions-consent.md) и [PRIVACY.md](PRIVACY.md).

## Удаление и хранение

- Активная ассоциация хранится до удаления пользователем.
- Tombstone остаётся в БД, чтобы удаление синхронизировалось; физическая очистка tombstone-строк и их текста пока не реализована.
- Удаление ассоциации не отзывает уже отправленные вклады: для этого нужно отдельное действие `POST /api/mnemonic-contributions/withdraw`.
- Изображение удаляется вместе с ассоциацией на устройстве; на других устройствах его и не было.
- Очистка данных приложения/браузера удаляет локальные изображения без возможности восстановления.
- Удаление аккаунта каскадно удаляет `user_mnemonics`, `contribution_preferences`, прогресс и подписки; вклады обезличиваются (`contributor_user_id = null`), потому что они нужны для истории модерации.

## Известные ограничения

- Нет резервного копирования и восстановления локальных изображений.
- Нет фоновой очистки осиротевших файлов изображений.
- Нет UI экспорта или удаления аккаунта.
- Rate limit вкладов не распределён между инстансами.
- Автоматическая публикация одобренных вкладов не реализована.
- Мобильная синхронизация требует VIP; веб-облако остаётся бесплатным.
